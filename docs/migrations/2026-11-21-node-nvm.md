# Node.js and nvm migration (2026-11-21)

This guide moves an existing `devcontainer-base` checkout from the Node.js Dev Container Feature and the npm-installed OpenSpec CLI to image-built Node.js, nvm, and the standalone OpenSpec binary. It covers the breaking change, the rebuild, verification, and rollback. The other nine Dev Container Features, including Docker-in-Docker, are unchanged.

## Breaking change

Node.js no longer comes from a Dev Container Feature. `.devcontainer/Dockerfile` installs Node.js `26.13.1` through nvm `v0.41.0` as the `developer` user under `/home/developer/.nvm`, and the image PATH includes `/home/developer/.nvm/current/bin`.

OpenSpec `2.1.1` is now a standalone binary at `/usr/local/bin/openspec` instead of an npm package that `post-create.sh` installed. `post-create.sh` verifies exactly `2.1.1` and does not install the CLI.

pnpm is no longer preinstalled. Run `npm install -g pnpm` to restore it under the nvm global prefix.

An existing container keeps the old feature-based Node and the npm-installed OpenSpec until step 1 recreates it from the new image.

## Changes

| Before | After |
| --- | --- |
| Node.js from the Node.js Dev Container Feature | Node.js `26.13.1` from nvm `v0.41.0` in `.devcontainer/Dockerfile`, installed as `developer` under `/home/developer/.nvm` |
| Node and npm on the feature-provided PATH | `/home/developer/.nvm/current/bin` on the image PATH, plus shell hooks for login and interactive shells |
| No nvm in the image | nvm `v0.41.0` installed in the image |
| `post-create.sh` installs `@fission-ai/openspec@2.1.1` with npm | Standalone OpenSpec `2.1.1` at `/usr/local/bin/openspec`, verified per architecture with a pinned SHA-256; `post-create.sh` verifies the version |
| pnpm available in the image | Not installed; run `npm install -g pnpm` |

## Migrate a repository

1. Update the checkout to the commit that contains this guide, then rebuild the container so the image provides Node.js, nvm, and the standalone OpenSpec binary:

   ```bash
   devcontainer up --workspace-folder . --remove-existing-container
   ```

   In VS Code, run **Dev Containers: Rebuild Container** instead. To undo this step, restore the previous commit and rerun the same rebuild command.

2. Confirm the toolchain inside the container:

   ```bash
   node --version
   nvm --version
   openspec --version
   ```

   The output must report `26.13.1`, `0.41.0`, and `2.1.1`. This step only reads versions, so it has no undo. The [Verify](#verify) section lists the full check.

3. If the repository pins a Node version in `.nvmrc`, select it explicitly:

   ```bash
   nvm use
   ```

   The shell hooks source `nvm.sh --no-use`, so opening a shell does not read `.nvmrc`. `nvm use` selects the version named there. Run `nvm install` first if the image does not provide it. To undo this step, run `nvm use default`.

4. Restore pnpm if the project uses it:

   ```bash
   npm install -g pnpm
   ```

   Run this after any `nvm use` so the package lands under the selected Node version. `/home/developer/.nvm` is not a named volume, so reinstall pnpm after every container rebuild. To undo this step, run `npm uninstall -g pnpm`.

## Where the toolchain lives

| Path | Contents |
| --- | --- |
| `/home/developer/.nvm` | nvm `v0.41.0` and the Node.js `26.13.1` install tree, owned by `developer` |
| `/home/developer/.nvm/current/bin` | `node`, `npm`, and `npx` for the default version; the image PATH includes this directory |
| `/etc/profile.d/00-nvm.sh` | Login-shell PATH entry and the nvm function |
| `/etc/bash.bashrc` | nvm function for interactive bash |
| `/home/developer/.bashrc` | nvm function for the `developer` user's shells |
| `/usr/local/bin/openspec` | Standalone OpenSpec `2.1.1` binary, independent of the nvm Node.js |

Each of the three shell files sources `nvm.sh --no-use`, so a shell never switches to a version named in `.nvmrc`; run `nvm use` when a repository pins one.

The nvm installer is checksum-pinned, and that checksum authenticates the installer text, not the cloned nvm tree. Node's tarball is verified by nvm against the same-origin `SHASUMS256.txt`, and `NVM_NO_SOURCE_FALLBACK=1` stops a failed binary download from falling back to a source compile.

`make`, `gcc`, `g++`, and `libc6-dev` are in the image, so native npm addons build through npm's bundled `node-gyp`. `post-create.sh` chowns `$HOME/.nvm` with the other runtime directories, so a container remapped to another UID can still run `npm install -g`.

## Verify

Run these inside the container in an interactive shell, where the nvm hooks are loaded:

```bash
node --version      # 26.13.1
nvm --version       # 0.41.0
openspec --version  # 2.1.1
npm prefix -g       # a path under /home/developer/.nvm
make --version | head -1
gcc --version | head -1
g++ --version | head -1
```

`pnpm --version` reports `command not found` until you run `npm install -g pnpm`; after that it prints the installed version.

The migration is complete when the three version checks report the pinned values, `npm prefix -g` prints a path under `/home/developer/.nvm`, and `make`, `gcc`, and `g++` each print a version.

## Rollback

Restore the commit you were on before step 1, or revert this change, then rebuild the container with the command from step 1. The Node.js Dev Container Feature returns with its previous `devcontainer-lock.json` entry, and reverting removes the nvm and standalone OpenSpec steps from `.devcontainer/Dockerfile`.

A rebuild discards `/home/developer/.nvm` because it is not a named volume. Reinstall pnpm and any global npm packages after you roll back.
