# Superpowers to OpenSpec migration (2026-11-20)

This guide moves an existing `devcontainer-base` checkout from the vendored Superpowers plugin to the OpenSpec 2.1.1 spec layer. It covers the breaking change, the per-repository initialization step, and rollback. Stores and the apply workflow are out of scope; the orchestrator keeps the implementation loop.

## Breaking change

The Superpowers plugin is no longer loaded. `.opencode/opencode.global.json` denies `plugin.use *`, and the vendored tree, lock file, local patch, and `scripts/update-superpowers.sh` are removed. OpenSpec 2.1.1 is a required CLI and requires Node.js 22.20 or newer.

A repository without an `openspec/` root stops the control plane. The control plane does not create the root implicitly.

## Changes

| Before | After |
| --- | --- |
| Superpowers plugin loaded by `.opencode/opencode.global.json` | No plugin; the global config denies `plugin.use *` |
| `.opencode/superpowers/`, `.opencode/superpowers.lock`, `.opencode/superpowers-local.patch` | Removed |
| `scripts/update-superpowers.sh` | Removed; `openspec update` refreshes the generated skills after a CLI pin change |
| Plan written after `task-enumerator` | `proposal.md`, delta specs, `design.md`, and `tasks.md` under `openspec/changes/<change>/` |

## Prerequisites

The container must run Node.js 22.20 or newer. Check it inside the container:

```bash
node --version
```

## Migrate a repository

1. Update the checkout to the commit that contains this guide, then rebuild the container so `.devcontainer/post-create.sh` installs the pinned CLI:

   ```bash
   devcontainer up --workspace-folder . --remove-existing-container
   ```

   In VS Code, run **Dev Containers: Rebuild Container** instead.

2. Verify the CLI version:

   ```bash
   openspec --version
   ```

   The output must report `2.1.1`. `post-create.sh` installs `@fission-ai/openspec@2.1.1` when the command is missing or reports another version.

3. Initialize OpenSpec once in each target repository:

   ```bash
   openspec init --tools opencode --scope project --profile core
   ```

   This creates `openspec/config.yaml`, `openspec/changes/`, `openspec/specs/`, and six `openspec-*` skills under `.agents/skills/`.

4. Commit `openspec/` and `.agents/skills/` in the target repository. The generated skills are committed so a fresh clone can use them without running `openspec update` first. If you have not committed yet, delete both directories to undo this step.

## Where artifacts live

| Path | Contents |
| --- | --- |
| `openspec/changes/<change>/proposal.md` | What the change does and why |
| `openspec/changes/<change>/specs/<capability>/spec.md` | Delta spec for each capability |
| `openspec/changes/<change>/design.md` | Approach, when the change is architectural or cross-cutting |
| `openspec/changes/<change>/tasks.md` | Ordered tasks, each with its failing test and verification command |
| `openspec/specs/` | Living specs, updated when a change is archived |
| `.agents/skills/openspec-*` | Six generated skills: propose, explore, apply-change, update-change, sync-specs, and archive-change |
| `.superpowers/sdd/` | Task ledger, briefs, and reports; a process directory, not a plugin dependency |

`/openspec-propose` creates the change artifacts. Do not run `openspec propose` as a shell command. `openspec archive` folds a completed change's delta specs into `openspec/specs/`.

## Verify

Run this inside the container:

```bash
openspec --version
```

The output must report `2.1.1`. After you create the first change, `openspec validate <change-name> --strict` checks its artifacts.

The migration is complete when every target repository has `openspec/config.yaml` and `.agents/skills/openspec-propose/SKILL.md`. `openspec --version` must report `2.1.1`, and `.opencode/opencode.global.json` must have no `plugins` key.

## Rollback

Restore the previous commit of this repository or revert this change, then rebuild the container. The previous commit loads the Superpowers plugin again and drops the OpenSpec requirement.

`openspec/` data in a target repository is separate from this repository. A rollback here does not delete it. Delete `openspec/` and `.agents/skills/` in a target repository only if you also want to remove the new artifacts; keep them if you plan to retry the migration.
